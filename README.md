# dsh-todo-freshness

DSH 的任务卡片（"任务 1 进行中 · 5 待处理"）只是**最后一次 `todo_write` 的快照**。模型做完活直接输出最终答复时，那一步没有工具调用，也就再也没有机会回写，于是面板会一直挂着旧状态。这个插件不替你改数据，而是把"这份清单已经过期"这件事说出来，并催模型自己回写。

## 两个部件

**Host（`index.js`）**

- 注册一个会话投影 `todoFreshness`，从既有事件里折叠出：上次写清单是什么时候、之后又跑了多少次工具调用、其中有多少次真的改了文件、清单里还剩几项没有结论、这一轮是不是已经结束。
- 在 `tools/post-execute` 上挂一个建议：当清单里还有未完成项、且从上次回写起已经连续跑了默认 6 次（以及 14 次）工具调用时，往下一步注入一条提醒，要求模型用真实状态整表重写。次数可配置，见下文。
- 不写 `todo/write`，不把 `pending` 改成 `completed`。没干完就是没干完。

**Client（`client.js`）**

- 在 `conversation.input.dock` 的 order 1 注册一条提示条，只在两种情况下出现：
  - `stale`：清单里还有未完成项，但已经连续超过阈值次工具调用没有回写；
  - `closedWithUnfinished`：这一轮已经结束，清单却还留着未完成项。
- 提示条只报测得的事实——"清单 12 分钟前写下，之后有 8 次文件改动"——不说"这些活已经做完了"。哪一项做完了插件无从得知，能从事件里数出来的只有"清单没动、但代码动了"，所以它就说这一句。
- 正常更新清单时它不出现，不会和内置的任务卡片抢位置。鼠标悬停可以看到当前生效的阈值。

## 为什么这么设计

两种"修法"里，只有一种不撒谎：

| 做法 | 效果 | 问题 |
|---|---|---|
| 轮次结束时把遗留项一律标成 `completed` | 面板永远干净 | 没做完的活也显示完成，等于伪造结果 |
| 如实标注 + 催模型回写 | 面板可能仍然显示未完成 | 但它显示的确实是真话 |

这个插件走第二条。清单"对不上"时你看到的是可核对的差距（几分钟前写的、之后改了几次文件），而不是一个看起来还在进行的假进度，也不是一句替你下结论的"还没跟上"。

## 配置

`cordis.patch.yml` 里的行可以带 `config`：

```yaml
- insert:
    - id: todo-freshness
      name: dsh-todo-freshness
      config:
        staleCalls: 10
        nudge: false
```

| 字段 | 默认 | 含义 |
|---|---|---|
| `staleCalls` | `6` | 连续多少次工具调用没有 `todo_write` 就算过期。做长任务嫌提示太频繁就调大，比如 `15` |
| `nudgeAt` | 跟随 `staleCalls` | 在第几次调用时注入提醒，可写多个。默认是 `[staleCalls, staleCalls * 2 + 2]`，即阈值 6 时是 `[6, 14]` |
| `nudge` | `true` | 是否注入中途提醒。关闭后只保留 Client 侧的标注，不产生任何模型请求 |

`staleCalls` 与 `nudgeAt` 的每一项都必须是 ≥ 1 的整数（写成 `"10"` 这样的字符串也认）。取值不合法时会退回默认值，并在插件日志里写一条 warning 说明忽略了哪个字段——不会静默失效。

## 限制

- 提醒只是建议。模型可以不理会它，这时面板依旧停在旧状态——插件不会替它决定。
- 阈值是经验值。默认 6 次是按"一次工具调用大概推进一个子任务"估的，实际任务粒度不同的话用 `staleCalls` 调。
- 触发看的是工具调用总数，提示条里引用的却是文件改动次数。读文件、跑 shell 也算调用但不会改代码，所以在连续跑命令的阶段，计数会先于真实进度到达阈值——把 `staleCalls` 调大就是给这类阶段留余量。
- 投影 key `todoFreshness` 是本插件私有的；卸载后它从会话状态里消失，不影响内置的 `todos`。

## 安装

`desktop` 这个 profile 只归桌面端管，命令行装不了：

```
$ dsh plugin --profile desktop add ...
error: profile "desktop" is managed exclusively by the Electron application
```

所以走桌面端的「插件」界面，或在会话里让 agent 用 `plugin_manager` 的 `install_bundle` 指定这个目录。装完在 bundle 列表里启用，刷新页面即可。

`index.js` import 了 `@deepseek-ai/dsh-llm`，所以 `peerDependencies` 里必须声明它——本地链接的包靠这份声明把 core 模块路由到应用自己的安装目录，漏了就报 `Cannot find module`。
